# 讲义主线

“主线”是讲义靠什么串起来。同一份材料，主线不同，写出来的讲义完全不同，所以**每门新课动笔前必须问用户**，不能自己定。

## 什么时候问、怎么记

- 新课（`制作记录/构建/<简称>构建配置.json` 里没有 `mainline` 字段）：在读完材料、定好范围之后，写正文之前问一次。用 AskUserQuestion，把**这种输入可选的**主线作为选项（见下表），每个选项配一句“这门课用它会是什么样”（结合材料举例，比如“每节从‘光线为什么走这条路’这道例题开始”）。
- 推荐项：用户以前说过偏好（记忆、AGENTS.md、别的课的 mainline）就推荐那一种；都没有时，课程类推荐“例题驱动”，领域类推荐“问题驱动”。
- 用户选定后写进配置的 `mainline` 字段（`new_project.py --mainline`）和本课制作记录的开头。之后的代理读到就照做，**不再问**；只有用户自己提出要换时才改。
- 用户不在场（批处理、子代理）时：用配置里的值；配置里也没有就用上面的默认推荐，并在交付说明里写明“主线未经用户确认”。

| 输入（`inputs.md`） | 目的 | 可选主线 |
|---|---|---|
| 课堂转写、单本教材 | 学会一门课：会做题，也懂理论 | 例题驱动、概念体系、课堂顺序（只限课堂转写）、题型归纳 |
| 领域 / 科研方向 | 真实学习：读懂前沿、知道问题和方法的来龙去脉，不为考试 | 问题驱动、发展脉络、概念体系、论文精读 |

领域类**不提供例题驱动和题型归纳**：这两种以题目为中心，适合应试；学一个研究方向时，题目不是目标。

## 课程类的五种主线

### 1. 例题驱动（课程类默认推荐）

用教材里的例题和习题把整章串起来：先做题，再从题里讲出结论和理论，最后附上习题。三条目标都要做到，覆盖表逐条核对：

1. **读完能做出范围内的全部题目**：老师课件（PPT）里的例题和练习、教材例题、章末习题，有作业的还包括作业。这是对“会做”的要求，**不是**每道题都要在讲义里占篇幅。讲义讲解的例题从这些题里挑：**课件题优先**，因为老师选进课件、在课上讲过的题最能反映重点和考法，通常归入“讲解”或“习题”；教材题补足课件没覆盖的知识点。只有这些题里都找不到合适的题来引出某个知识点时才自编，记录里注明“编者补充”。按题目的分量分四档处理：
   - **讲解**：典型、能引出知识点的题，作为例题完整讲（每小节 1—2 道）。
   - **习题**：和例题同型、换了条件的题，附在小节末，带折叠的提示和解析（每小节最多 3 道）。
   - **折叠 / 带过**：比较边缘的题（计算繁琐、偏、只是换个数字），不单独成题。要么放进小节末一个折叠的“更多课本习题”，每题一两行：题目要点（含关键数据）→ 关键一步或答案；要么在正文里一句话带过（“把例 3 的圆环换成圆盘，做法相同，结果见结论 2”）。
   - **同类**：和某道例题或习题完全同型的题，讲义里不出现，只在覆盖表里写“同类：例 k”。
   宁可少讲几道，也不要让讲义被题目淹没；拿不准时归入折叠。
2. **覆盖教材范围内的全部概念、定义、定理、证明和应用**。例题是讲理论的入口，不是理论的替代：教材证明了的定理，讲义也要证明（可以改写得更好懂，不能省）；教材略去证明的，给出推导思路，或写明“证明超出本书范围”。教材讲到的应用（物理意义、工程应用、与其他章节的联系）也要写。
3. **顺序**：例题 → 结论与理论 → 习题。

每个 `### N.M` 小节的顺序：

1. 一两句话交代问题从哪来（不写“接下来我们讨论”）。
2. `::: {.block .example}` **例 k · 写明对象和所求量**：完整题干，有图配图，然后分步求解。一个小节 1—2 道（第二道通常是变式，换条件或换问法，写一两句话说清它和上一题的区别）。
3. 理论，从刚做完的题里讲出来：
   - `.definition`：题里碰到的量，在这里给出正式名字和定义；
   - `.theorem` 或 `.result`：一般结论，写明成立条件；
   - 证明或推导紧跟在定理块后面的正文里，以“**证明。**”开头；
   - 应用：一两段说明这个结论还能解决哪些问题、和前后章节怎样联系。
4. 需要时 `::: {.block .warning}`：这类题最容易错在哪（“错误做法 → 错在哪里 → 正确做法”）。
5. 小节习题：每题一个 `#### 习题 k · 对象与所求量 {#practice-k}`（k 全篇连续编号），0—3 道，从教材习题里挑，优先选和本节例题同型、换了条件的题。题干完整，然后是“提示”和“解析”两个 details。
6. 需要时，小节最后放一个折叠的边缘题清单：

   ```
   <details><summary>更多课本习题 · 3 道</summary>

   - 圆盘换成圆环、求轴线上的场（$R_1=2$ cm，$R_2=5$ cm）：把例 4 的积分下限改成 $R_1$，结果 …
   - …

   </details>
   ```

全篇最后一个单元是 `## N 综合练习与概念检查 {#practice}`：放跨小节的综合题（`### P1 … {#practice-p1}`，可以没有），以及 `### C 概念检查`。

**覆盖表**（写在本课制作记录的“覆盖表”一节，写正文前列好条目，写完填讲义位置，再跑 `coverage_check.py`）：

```
| 来源条目 | 类型 | 处理 | 讲义位置 |
|---|---|---|---|
| 课件第 3 讲 p.12 例题 | 课件题 | 讲解 | 例 2 |
| 例 4.1（p.112） | 例题 | 讲解 | 例 3 |
| 习题 4-2 | 习题 | 习题 | 习题 5 |
| 习题 4-5 | 习题 | 折叠 | #fermat |
| 习题 4-6 | 习题 | 带过 | #fermat |
| 习题 4-7 | 习题 | 同类 | 例 6，结论 4 |
| 定理 4.2 费马原理 | 定理 | 讲解 | 定理 2 |
| 定理 4.2 的证明 | 证明 | 讲解 | #fermat-proof |
| 4.3 节 光纤 | 应用 | 讲解 | #fiber |
```

类型取 课件题 / 作业 / 例题 / 习题 / 概念 / 定义 / 定理 / 证明 / 应用，以及下面“知识点清单”的 术语 / 对比 / 方法 / 课堂讨论 / 思考题；处理取 讲解 / 习题 / 折叠 / 带过 / 同类（见上面第 1 条）；讲义位置写块标题的“类别 编号”（例 k、习题 k、P k、定义 k、定理 k、结论 k）或小节 id `#…`，同类写它所依据的例题和结论。覆盖表是制作记录里的核对清单，不是讲义的一部分：范围内课件的每道题、教材的每个例题、每道章末习题、每个定义和定理都占一行，保证没有漏掉、都能做；但大部分习题应当是“折叠”“带过”或“同类”，讲义本身保持紧凑。

**知识点清单：理论行要从五种独立来源列出，不能从写好的正文里抄。** 题目行天然齐全（课件、教材、作业逐题列），理论行却容易只抄教材编号的定义和定理，或抄自己已经写出的块；这样漏掉的东西 coverage_check 永远看不见。大学物理 v7 被用户连续指出五处缺失，全部属于下面后四类：导体电势怎么算（方法）、介电强度（术语）、串联为什么电量相等（证明只断言没讲原理）、断开电源与接着电源时各量怎么变（对比）、电压不变时电源也做功（课堂讨论）。写正文前，按下面五种来源各列一遍，类型照写：

| 来源 | 类型 | 怎么找 | 例子 |
|---|---|---|---|
| 教材的定义、定理、证明、应用、表格 | 定义 / 定理 / 证明 / 应用 | 每节小标题、黑体字、带编号的公式、表格 | 表 10.1 介电常数与电介质强度 |
| 范围内全部题目题干里的术语和条件说法 | 术语 | 逐题读题干，包括折叠、带过、真题：不认识就做不了题的词都列 | 介电强度、充电后断开电源、接地 |
| 老师总结的方法与步骤 | 方法 | 转写里搜“几种方法”“步骤”“小结”“牢牢记住”“抓住” | 求电势的三种方法、导体电势的求法 |
| 同一种操作在不同条件下出现在两道以上的题里 | 对比 | 按操作归类题目：插介质、拉极板、接地、串并联…… | 电量不变与电压不变 |
| 老师课上专门停下来讨论、追问或留的思考题 | 课堂讨论 | 转写里搜“思考题”“为什么”“注意”“很容易”“区别” | 接着电源时 E 为什么不是 E0/εr |
| 教材每章的思考题 | 思考题 | 章末“思考题”，可以折叠作答 | 思考题 10.12 充煤油 |

写进正文时：术语加粗给出定义，放在第一道用到它的题之前或紧跟其后，与容易混淆的量对照（介电强度 vs 介电常数）；方法和对比写成结论块，对比用表格列出每种条件下各量怎么变，块末列“用到它的题”，不能只散在各题的解答里；课堂讨论写成段落或结论，注明老师原话的日期。某类确实没有（例如没有转写就没有“课堂讨论”），在覆盖表一节写一行“不适用来源：课堂讨论（只有教材）”。coverage_check 会检查五类是否都有行，并检查每个术语在讲义里加粗出现。

**写完每个单元做一次学生视角自查。** 把这个单元的每道题（含折叠和真题）的解答过一遍，列出它用到的每个术语、条件判断和原理，逐个确认在这道题之前已经讲过、讲到了“为什么”。凡是“这一步凭什么”答不上来的，就是漏掉的知识点，补进清单和正文。清单检查的是“有没有列”，这一步检查的是“列得全不全”，两者不能互相代替。

**已有讲义返工时，再按转写逐块对照一遍。** 大学物理 v7 全书排查（46 块转写）在五种来源之外又找出三类缺口：①“为什么”缺失：正文只给结论，老师讲的动机没写（为什么除以 $q_0$ 定义电势、为什么用面积矢量定义磁矩、为什么还需要环路定理）；②体例漂移：前几单元的例题都有“思路”，后面单元一处都没有，写长讲义时越往后越容易只剩解题过程，每单元收尾检查一次；③课堂口误和交叉引用错：老师的说法也要按物理核对（例如说导线中的直流不均匀），引用的定理编号要对。对照时每块转写记“✔ 已有 / ✘ 缺 / △ 不够清楚”和要改到哪里，先记全再统一改，改完把排查文件留在制作记录里。

正文写完后填“讲义位置”最省事的办法：写一个小脚本按顺序扫正文 md，记下当前小节 id 和当前块（例 k、习题 k），遇到“（教材例 x.y.z）”“（作业 x.y）”就记为讲解或习题，遇到“更多课本习题”折叠栏里的 `- **习题 x.y**` 就记为折叠 `#小节id`，其余提到的记为带过；再与教材 OCR 列出的全部题号比对，补上范围外和课堂例题。电子电路 v3 用这种办法一次生成 240 行。数值例题核验时用精确值：教材常把中间角度取整，差在第三位有效数字时正文两者都给。

扫描脚本的两个坑（大学物理 v6）：一处来源标注可能列出几道题（“（教材例 9.11、9.12）”），要把顿号后的编号也记上；一行合并了几种处理时 coverage_check 会报错，“处理”只能写一个值，按 讲解 > 习题 > 折叠 > 带过 > 同类 取最重的那个。题图与题文矛盾（如图画成沿轴等距、题文说沿球面均匀）时两种理解都算出来，写明差别。旋转带电体、非匀强磁场中的力和力矩，用数值 Biot–Savart 或 sympy 复核符号，转写里板书的正负号不直接采信。全书重写后旧的词语荧光几乎全部匹配不上（v6 只剩 6 处），直接重写，不要逐行修补。

单元格里的竖线写成 `\|`，或放在 `$…$`、反引号里；coverage_check 按其余竖线切分。

已有讲义中途改用例题驱动（只重写新单元）时：新单元的小节要加 ascii id（`{#taylor-shift}`），概念关系 `@` 键随之改成这些 id，旧的按标题写的键要手工替换；段落重排后词语荧光的行也要按页面顺序挪到新位置。format_check 不检查全书主线是否一致，这种混合写法要在制作记录里说明。

### 2. 概念体系

按学科自身的逻辑：定义 → 性质 / 定理 → 证明或推导 → 例题应用。适合证明为主的数学课（线性代数、分析），或用户想系统打基础时。

每个小节：`.definition` → `.theorem`（含证明或推导）→ `.example`（应用）→ `.warning`（常见误解）。

### 3. 课堂顺序

跟着老师上课的顺序、例题和讲法走，讲义像一份整理好的课堂笔记，便于对照上课进度复习。只在有课堂转写时可选。

小节顺序与课堂一致，例题保留老师选的题和讲解思路；口误、课件错误照常纠正，只记在制作记录里。

### 4. 题型归纳

以考试题型为单位：识别特征 → 方法步骤 → 典型例题 → 易错 → 练习。适合考前复习、题型稳定的课程。

每个 `## N` 是一类题型；`### N.M` 依次是“怎么认出这类题”（`.result`）、“步骤”（`.theorem` 写成编号步骤）、“典型例题”（`.example`，至少两道，难度递增）、“易错”（`.warning`）。

### 5. 真题驱动（有历年卷时推荐；例题驱动的变体）

用户有历年期末卷、小测原卷，想“第一次学就面向考试”时用（2026-10 概率论 v4）。在例题驱动的基础上改三处：

- **第 0 单元“考试地图”**：统计每套卷的题型、分值、出现次数，表里给出讲义位置；写清小测的时间、题量、给分（从转写里找老师原话）；再写一段备考用法（遮住解答限时做、写过程的四步、考前顺序）。
- **每小节开头换成真题**：能找到就用一道【真题】或【小测】例开头，第一行斜体写来源、原卷分值和建议用时，如 `*2016—2017 秋冬期末 A · 第二题第 (1) 问（约 5 分）· 建议用时 6 分钟*`；大题解答末尾写**评分要点**，填空、选择写**考点**。教材和课堂例题放在后面讲原理。小节习题里真题、小测排在课本习题前面，课本边缘题折叠。
- **限时卷单元**：放在综合练习之前，每份卷按小测规格配题（小测原卷原样给出；期末大题拼卷；自拟题不标【真题】），解析里给评分要点，供读者计时自评。

范围仍按授课进度：超范围的真题小问注明“第 4 章再做”，整题超范围的只在覆盖表里带过。真题答案要和答案卷、核验脚本三方对齐，流传答案的错误记进制作记录。覆盖表加“期末 / 小测 / 线上小测”各行，每个小题一行。coverage_check 的篇幅提醒在高频小节会偏多，是有意的。

2026-10 大学物理 v7 的补充：

- **评分要点只写原卷给出的分值。** 答案卷没有分步分值时写“得分步骤（原卷未给分步分值）”，只列步骤，不编分数。
- **真题与教材题重合时不重复写。** 在原题标题加【真题】、标题下加斜体出处行，新写的真题例里用编号指过去。
- **已有讲义改成真题驱动时用拼装脚本。** 从备份的旧源稿出发，插入块（`@@ LEAD/PRACTICE/MORE/TAG <小节 id>`）先用 `~h4` 这类临时编号，最后统一重排例、习题编号并改全部引用；脚本可重复运行。词语荧光要按页面顺序重排、改编号；概念关系给限时卷小节补“用到”行。
- **coverage_check 的“折叠”只认“更多课本习题”和“教材思考题”开头的栏。** 收进“更多真题”栏的一行带过，覆盖表处理写“带过”。
- **小测题型池页面**（`复变小测题型池.html`、`大学物理小测题型池.html` 为例）：独立页面、单独构建配置、单独中文字体子集（不覆盖主讲义的子集）。按小测次序分单元，每单元按题型分池：`结论 · 固定动作` 块 → 池中全部题目表 → 两个班原题 → 历年同型题；最后一单元把原卷原样排成限时模拟，再加概念检查和来源说明。超出主讲义进度的池，固定动作写成带条件、可单独使用的公式，并注明“讲义尚未讲到”。

## 领域类的四种主线

学一个领域或科研方向是真实学习：读完要能读懂这个方向的论文，知道核心问题是什么、方法为什么这样发展、哪些问题还没解决，并能自己动手算一个小例子或复现一个小实验。不追求题目覆盖，也不写应试技巧。

这四种主线里，`.example` 块写的是**具体例子**（一次手算、一个玩具模型、一个实验现象），不是考题；标题照样写“例 k · 对象”。

### 1. 问题驱动（领域类默认推荐）

从这个方向要解决的真实问题出发。每个 `## N` 是一个核心问题；小节依次是：问题是什么、为什么难（`.result` 写清难点）→ 最简单的具体例子（`.example`）→ 已有方法怎样一步步推进（`.definition`、`.theorem` 写关键概念和结论，附推导）→ 各方法的局限（`.warning`）→ 尚未解决的问题。

### 2. 发展脉络

按关键工作的先后顺序：每个 `### N.M` 是一项工作（或一组同期工作），写它之前的方法卡在哪里、它提出了什么、为什么有效、又留下了什么问题。适合想知道“这个领域是怎么走到今天的”。

### 3. 概念体系

同课程类的概念体系，用在理论成熟的方向（例如某个数学分支）。

### 4. 论文精读

以 3—6 篇核心论文为单元，每个 `## N` 一篇：要解决的问题 → 方法 → 关键推导（补全论文省略的步骤）→ 实验和结论 → 局限与后续工作。适合用户已经选好要读的论文时。

## 不随主线变化的格式（保证不同代理写出的页面一致）

无论选哪种主线，下面这些都相同，`format_check.py` 会逐项检查：

- 开头：`# 标题`（本讲义的主题，如“费马原理”），接一行加粗的来源说明，固定写成
  - 课堂转写：`**<课程名> · <教师>课程学习讲义（<范围>）**`
  - 单本教材：`**<课程名> · 《<书名>》学习讲义（<章节范围>）**`
  - 领域 / 科研方向：`**<领域名> · 学习讲义（<主题范围>）**`

  再写两三段导言（这部分讲什么、按什么主线展开、需要哪些预备知识）；然后 `## 学习路线`，用表格列出各单元。
- 单元划分：跟着来源的下一级标题走。教材某节下分 4.1、4.2、4.3，讲义就是单元 1、2、3，再加一个练习单元；不合并、不拆分。课堂转写按一次课或一个完整主题划单元。领域类按所选主线划（一个核心问题、一段时期或一篇论文一个单元）。小节（`### N.M`）由你按例题和知识点划分。
- 单元 `## N 标题 {#英文id}`，小节 `### N.M 标题 {#英文id}`；id 只用小写字母、数字、连字符。
- 语义块只用五种：definition、theorem、result、example、warning。块的第一段是单独一行加粗标题，写成“类别 编号 · 名称”：`**定义 1 · 光程**`、`**定理 2 · 费马原理**`、`**结论 3 · 光程差决定相位差**`、`**例 4 · 球面折射的成像位置**`、`**易错 · 把几何路程当成光程**`。定义、定理、结论、例各自全篇连续编号；易错不编号。例题标题写明对象和所求量，不写“例题 · 先读条件”这类泛称。
- 例题必须有解答，解答直接写在块里（不折叠）；练习的答案才折叠。
- 练习：每题一个带 `practice-` id 的标题，题干完整，然后 `<details><summary>提示 · …</summary>` 和 `<details><summary>解析</summary>`。不要用 `### E1`、`### Q1` 这类不带 practice- id 的题目标题。
  - 例题驱动：小节习题挂在小节末尾，`#### 习题 k · 名称 {#practice-k}`；综合题放在最后的 `## N 综合练习与概念检查 {#practice}`。
  - 其他主线：集中放在练习单元 `## N 练习与概念检查 {#practice}`（篇幅长时每章一个），每题 `### P1 标题 {#practice-p1}`。
  - 领域类：练习单元写成 `## N 思考与动手 {#practice}`，放开放问题、补全推导、小型复现任务；“解析”写参考思路，不必唯一答案。
- 练习需要范围外的图或条件（例如前一节的示意图）时可以引用，但题干要写完整、图要配上，并在记录里注明。练习的题图紧跟题干，构建脚本会把题干、公式和题图一起装进练习块。
- 练习单元最后是 `### C 概念检查 {#practice-concepts}`：判断题，每题一个“核对” details。
- 领域类在练习单元之后加 `## N 参考文献 {#references}`：正文里的事实、年份、实验结果都要能在这里找到出处；没有出处的不写。
- 图：`![图注](资源/<简称>原图/xx.png)`，图注写清图中记号与正文的对应。
